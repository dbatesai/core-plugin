# Round 2 — Premise attacker

Reviewing v2 of D1–D4. Mandate: argue that CORE should not exist, or that v2's two-layer answer is the wrong shape for the owner's real use. Round-1 findings R1-PA-01 to R1-PA-11 and the other reviewers' files were read first. Nothing below repeats them. Where a round-1 fix is wrong or incomplete, the finding says so and cites the earlier ID.

## The strongest case

v2's two gates are decided before they run. Its own Layer 1 cannot ship without its Layer 2. The arm called "convention" is not Layer 1. It is three lines of `AGENTS.md` text, with no skills. Those three lines never mention due items and never say to write anything down. So the four-arm gate passes on `proactive-due` alone, because (0 + 0 + 1) / 3 = 0.33, which clears 0.3. And the ten-session gate passes on write rate by construction. Both results will be credited to the hooks, when what they measure is "five skills plus hooks" against "a three-line note". Meanwhile Layer 1, the part said to ship "unconditionally" with "no code", sits inside the plugin folder. Every one of its five skills calls `core.mjs`, and it searches an index that only the script writes and git ignores. If Layer 2 is dropped, there is nothing to ship. Even if it is kept, Layer 1 never reaches a cloud session. The same skills, committed to the repo's `.claude/skills/` and `.agents/skills/`, would reach Codex, Antigravity, and most Claude Code cloud sessions with no install and no enabled list. For this owner, the native stack also covers more than v2 admits. Claude Code's auto memory has a `project` type for "ongoing work, deadlines, and decisions", and loads its index into every session. Claude Code Projects keep a project memory across cloud threads, show what is "Waiting on you", send desktop notifications, and run scheduled tasks while the laptop is shut. No v2 gate compares CORE with any of that. The plan has no condition under which CORE itself would be retired. So the defensible product is a **committed repo template**, not a plugin: the record layout, five plain skills with no script calls, an `AGENTS.md` block that also covers due items, a `CLAUDE.md` import line, and one scheduled-task prompt. It should be measured against auto memory. Code should exist only if it beats that template, and v2 never runs that comparison. I still do not argue for mem0, Zep/Graphiti, Letta, claude-mem, or basic-memory as replacements. For this owner, plain files in the project remain right. The case against CORE as a plugin holds. The case against CORE as a convention does not.

- **Suggested fix:** Gate per job (recall separately from speak-up), not on a pooled mean. Give the convention arm the same "say what is due at session start" rule the `core` skill has. Report `proactive-due` as "hook beats an instruction to do the same", which is the only thing it can show.

### R2-PA-03  —  critical
- **Artifact:** D3 / D1
- **Location:** D3 step 7.7, "**write rate** — how many of the five planted facts appear, by regex, in any file under the folder (or, for the builtin arm, also under the built-in memory folder…)". Step 9.4, "**or** in step 7.7 the plugin's probe score beats the convention's by at least 1 (of 5) on the mean, with a write rate no lower".
- **What is wrong:** The second branch of the OR is near-certain to pass for reasons unrelated to the wiring. (1) The convention arm's only instruction is the block, which says nothing about writing. The plugin arm has the `remember` skill, whose description fires on "a decision made or reversed… even in the middle of another task". (2) Auto memory stays on in **every** arm, because the sessions run without `--bare`. So "write rate no lower" is met trivially. (3) Probe score then compares plugin plus auto memory against block plus auto memory, three repetitions each. A one-probe mean difference over three runs is inside the noise D4 Part 1 §2 already admits. An OR of two noisy tests roughly doubles the chance that Layer 2 is kept by luck.
- **What breaks if we ship it as-is:** The test the judge added to stop the gate failing CORE for the wrong reason (R1-PA-03) now passes it for the wrong reason. Layer 2 can fail the four-arm gate outright and still be kept on 7.7.
- **Suggested fix:** Count each arm's writes wherever that arm's memory lives, auto memory folder included, for all arms. Give the convention arm the `remember` skill (R2-PA-01). Replace the OR with an AND, or require the 7.7 margin to exceed the spread seen across repetitions.
